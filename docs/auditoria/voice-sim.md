### voice-sim-3 [high / bug] src/services/simuladorVozService.js:162
- Problema: Speech has a race condition. A stopped or replaced falar() call can still start text-to-speech of the old question, and the fallback can run twice. pararFala() pauses the Audio while play() is still pending, the promise rejects with AbortError, and the catch runs tocarViaWebSpeech() for the stale text. That stale call adds karaoke timers to the new call's global currentTimers, and its handleFinish→onEnd later sets isSpeaking=false in the middle of the new question. If a file fails to load, both audio.onerror and the play() rejection fire, so the question is spoken twice. Under React 18 StrictMode, mount→cleanup→mount triggers this on every question.
- Evidência: `audio.onerror = () => { currentAudioElement = null; tocarViaWebSpeech(); };` and `playPromise.catch(() => { tocarViaWebSpeech(); });`. There is no cancellation token. pararFala only does `currentAudioElement.pause()` and leaves the src loaded. Videochamada l.201-203 calls pararFala in the effect cleanup on every stepIndex change.
- Correção: Add a module-level `let falaGen = 0;`. pararFala(): `falaGen++`, clear the handlers, then `audio.removeAttribute('src'); audio.load();`. falar(): `const gen = ++falaGen; const alive = () => gen === falaGen;` and guard every callback (onloadedmetadata, onended, onerror, catch, utterance.onend, each timer) with `if (!alive()) return;`. Add a local `let fellBack = false; function fallbackOnce(){ if (fellBack || !alive()) return; fellBack = true; tocarViaWebSpeech(); }` and call it from both onerror and catch. In catch, ignore `err.name === 'AbortError'`.
