### procedures-1 [high / bug] src/components/procedures/EnfereClinicalPlayer.jsx:251
- Problema: YouTube progress, duration and completion are invented. A 1-second setInterval adds `playbackRate` to currentTime whether the iframe is playing, buffering, paused from inside the iframe, or not loaded yet. Duration comes from the text label ('11 min' becomes 660 s), and onComplete fires when that guessed value is reached. The side effect also runs inside a setState updater, which StrictMode calls twice. Commands sent before the iframe finishes loading are lost, so the cover disappears, the bar advances and the video never starts.
- Evidência: const interval = setInterval(() => { setCurrentTime((prev) => { const next = prev + playbackRate; if (totalDuration > 0 && next >= totalDuration) { setIsPlaying(false); onComplete?.(); return totalDuration; } ... }, 1000);  plus  const match = duration.match(/(\d+)\s*min/i); setTotalDuration(parseInt(match[1], 10) * 60);
- Correção: Drop the simulated clock. Load the iframe with enablejsapi=1. In its onLoad handler, post {event:'listening',id:1} to https://www.youtube-nocookie.com, and add a window 'message' listener that accepts only event.origin === 'https://www.youtube-nocookie.com'. Parse data.event === 'infoDelivery' and read info.currentTime, info.duration and info.playerState (1 = playing, 2 = paused, 0 = ended). Drive isPlaying, currentTime and totalDuration only from those values. Call onComplete in an effect when playerState becomes 0, guarded by a ref so it runs once. Queue play/seek commands until the first infoDelivery arrives (playerReady ref). The alternative is the official IFrame API (YT.Player with onReady and onStateChange).
